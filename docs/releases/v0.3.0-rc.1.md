# envwrap v0.3.0-rc.1

首个 GitHub Release，**预发布候选版**。这是新运行模型的完整源码与二进制交付，不是“真实 Claude 全场景已通过”的生产稳定认证。

## 这一版提供什么

- `envwrap claude` 保留原 HOME、Claude 登录/配置来源、项目、工具链和应用设置；`envwrap run -- ...` 使用同一个引擎。
- rootless Linux 透明 TCP：HTTP CONNECT / SOCKS5，支持 IPv4/IPv6；默认 DNS 经代理 TCP；对外非 DNS UDP 阻断。
- 明确的 localhost、LAN、内部 DNS 与文件路径 Unix socket 受信例外；故障不回退宿主外网直连。
- 稳定 schema 2 profile 与可识别的 Linux 容器身份视图；不查询 GeoIP，不在每次运行时重新随机化。
- doctor、真实终端/信号/退出管理、宿主 loopback TCP 回调，以及详细中文文档。

## 下载资产

| 文件 | 内容 |
| --- | --- |
| `envwrap-v0.3.0-rc.1-x86_64-unknown-linux-gnu.tar.gz` | Linux x86_64 GNU 二进制、文档、MIT 许可证、BUILD-INFO.json |

| `SHA256SUMS` | 上述两个包的 SHA-256 校验和 |

二进制最高 GLIBC 符号需求 **2.39**，需要 `libgcc_s.so.1`；构建主机 glibc 为 2.43。不是通用静态二进制；更旧 libc、ARM、musl 请勿把此资产当成已验证支持。

运行依赖：Linux rootless namespaces、支持 `--ro-overlay` 的 bubblewrap（已验证 0.11.1）、iproute2、nftables、相关内核功能和已安装的时区/locale。日常启动不需要 sudo，不修改宿主网络策略。

仓库仍为私有仓库；下载需要相应 GitHub 访问权限。校验和不是代码签名或独立安全审计。

## 使用顺序

1. 下载并验证 SHA256SUMS，先用解压后的二进制或 `envwrap-rc` 并行试用，不直接覆盖旧入口。
2. 显式配置代理来源变量、DNS、时区、locale，创建新的 schema 2 profile；已有旧 `default` 时用不同名称。
3. 运行 doctor，再用同一原生 Claude 配置做真实对话、流式响应、退出和 `--resume` 验收。
4. 验证你实际使用的 MCP/hooks/插件/skills、Git/SSH agent 和 OAuth 回调；通过后再切换日常入口。

完整步骤在仓库/压缩包的 README；配置参考、架构、故障排查及发布流程位于 `docs/`。

## 已完成验证

- 格式检查、Clippy 严格检查、全量 8 项回归、锁定依赖 release 构建。
- 实际优化二进制的 HTTP CONNECT 与 SOCKS5 端到端场景：TCP/UDP/DNS、IPv4/IPv6、身份、原环境、PTY/信号/退出、进程清理、真实 Git clone 与 OpenSSH agent。
- 发布前真实 Claude Code 2.1.302 的版本、帮助、认证状态和配置路径与原生启动对照；当时原生 Claude **未登录**，不能把这一点当作真实会话验收。

## 破坏性变化

旧 export/import/check/wrap、公开文件 sandbox、环境白名单、独立 HOME、强制遥测禁用和 telemetry-lab 已删除。旧 profile 不静默迁移，无兼容别名；请先保留旧二进制及私有配置备份。

## 仍需明确接受的边界

- 真实 Claude 登录后的对话、恢复及 MCP/hooks/插件/skills/OAuth 专项验收尚未完成，因此保持 **Pre-release**。
- 代理端点只接受 IP 字面量；不支持 HTTPS 代理或 SOCKS5 UDP ASSOCIATE，对外 QUIC 被阻断。
- localhost TCP 回调采用 50 ms 间隔发现，存在短暂竞态；不保证与共享宿主网络完全等价。
- 受信本机/LAN/Unix socket 服务可再自行联网，其后续请求不受 envwrap 控制。
- 不控制所有遥测，不改写 HTTPS，不隐藏所有宿主信息，不防恶意同用户进程，也不是文件安全沙箱。

此次发布不自动改变仓库可见性，不自动安装到用户 PATH，不修改或上传用户的真实 profile/代理凭据。
