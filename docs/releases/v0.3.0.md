# envwrap v0.3.0 — 通用透明运行环境

**正式版，2026-10-19。** 操作者已完成本机测试并确认发布。源码与 GitHub 资产来自同一最终提交；crates.io 上传是独立步骤，以注册表实际收录为准。历史 v0.3.0-rc.1 不覆盖。

## 通用启动

```sh
envwrap claude
envwrap codex
envwrap agy
envwrap git fetch
envwrap --profile work python3 program.py
```

Claude、Codex、agy 都是 PATH 中的普通程序，不是 envwrap 子命令。程序名后所有参数原样交给程序。`profile`、`doctor` 是管理名，`envwrap -- doctor` 可以转义；旧 `envwrap run -- PROGRAM` 改为 `envwrap PROGRAM`。

保留原 HOME、登录/配置来源、项目、工具链和应用设置。程序需要自行安装；envwrap 不创建账号分区或自动登录。

推荐 `socks5h://`：A/AAAA 使用会话内路由地址，连接以域名交给 SOCKS5 代理解析；不再与 `socks5://` 互为别名。SOCKS5 默认通过固定 HTTPS 出口观察选择 DNS 地址族偏好，可用 `network.dns_preference` 显式覆盖并跳过观察。单栈结果保留，未知状态不直连兜底。合成地址、DNSSEC、NXDOMAIN、加密 DNS 与内部后缀的兼容边界见[配置参考](../configuration.md)。


## 最终验收

标准为 `envwrap-independent-v2`：独立 syscall/procfs/sysfs/文件观察、host-child 对照、真实 TCP/DNS/UDP 与生命周期行为；分别验证 HTTP CONNECT、SOCKS5、SOCKS5h 及地址族偏好，可选只读参考 claude-code-env-checker 交叉扫描。

不再要求 Claude 登录或模型对话，不以风险评分为零作为验收。发布脚本对实际发布二进制运行独立检测和 checker 的身份/时区/接口/resolver/硬件继承核对，并在资产中提供 `ACCEPTANCE.json` 与 `BUILD-INFO.json`。应用内部遥测与服务端判断仍不属于可证明范围。

## 资产与安装

发布资产：

- `envwrap-v0.3.0-x86_64-unknown-linux-gnu.tar.gz`：程序、文档、许可证、BUILD-INFO.json、ACCEPTANCE.json。
- `envwrap-v0.3.0-source.tar.gz`：精确提交的完整源码。
- `SHA256SUMS`。
- 可通过 Git 标签安装：`cargo install --git https://github.com/jacek4yang/envwrap --tag v0.3.0 --locked`。
- crates.io 收录 `envwrap` 0.3.0 后，可执行 `cargo install envwrap --version 0.3.0 --locked`。GitHub Release 存在不代表 registry 已收录。

GNU 二进制的具体 libc/动态库要求记录在 BUILD-INFO；不声称支持未验证的架构和 musl。运行依赖为 Linux rootless namespaces、支持只读 overlay 的 bubblewrap、iproute2、nftables、相关内核功能和已安装的时区/locale。

## 明确边界

- 默认外部 TCP 与 DNS 走所选代理；不支持的外部 UDP 阻断，而非直连。
- localhost、显式 LAN/内部 DNS、文件路径 Unix socket 是受信例外。
- 宿主 TCP 回调端口发现间隔 50 ms，存在短暂竞态，不等价于共享宿主网络。
- 代理端点为 IP 字面量，不支持 HTTPS 代理或 SOCKS5 UDP ASSOCIATE。
- 不改写 TLS/遥测正文，不伪造完整物理机，不隔离恶意同用户程序，不隐藏所有宿主文件信息。
- profile 时区/locale 不改变代理实际出口 IP 或地理位置。

实际使用前创建完整 profile 并运行 doctor。原生应用登录与体验由操作者自行完成，不向 envwrap 提供账号密钥。
